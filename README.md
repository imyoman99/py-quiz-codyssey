## 4. 기능 목록

### 필수 기능
| 번호 | 기능 | 설명 |
|:---:|------|------|
| 1 | 📝 퀴즈 풀기 | 저장된 퀴즈를 출제하고 정답/오답을 판정, 결과 표시 |
| 2 | ➕ 퀴즈 추가 | 문제·선택지 4개·정답 번호를 입력받아 저장 |
| 3 | 📋 퀴즈 목록 | 등록된 전체 퀴즈 확인 |
| 4 | 🏆 점수 확인 | 최고 점수 확인 (풀 때마다 자동 갱신·저장) |
| 5 | 🚪 종료 | 데이터 저장 후 안전하게 종료 |

### 보너스 기능 (구현 완료 ✅)
<!-- ✏️ 실제 구현한 것만 남기고, 안 한 건 줄 삭제 -->
| 기능 | 설명 |
|------|------|
| 🎲 랜덤 출제 | `random.shuffle`로 문제 순서를 섞어 출제 |
| 🔢 문제 수 선택 | 풀 문제 개수를 사용자가 선택 가능 |
| 💡 힌트 기능 | 힌트 확인 가능, 사용 시 점수 차감 |
| 🗑️ 퀴즈 삭제 | 등록된 퀴즈 삭제 후 파일에 반영 |
| 📜 점수 히스토리 | 날짜/시간·푼 문제 수·점수를 모두 기록 |

### 예외 처리
- 공백 포함 입력 → 앞뒤 공백 제거 후 처리
- 숫자가 아닌 입력(`abc`) / 범위 밖 숫자(`9`) / 빈 입력 → 안내 후 재입력
- `Ctrl+C`, `EOF` 발생 시 → 데이터 저장 후 안전 종료
- `state.json` 없음/손상 시 → 기본 퀴즈 데이터로 복구

## 7. 데이터 파일 설명 (state.json)

| 항목 | 내용 |
|------|------|
| **경로** | 프로젝트 루트 `./state.json` |
| **역할** | 퀴즈 목록과 최고 점수를 저장하여 재실행 시에도 데이터 유지 |
| **인코딩** | UTF-8 |
| **생성 시점** | 첫 저장 시 자동 생성 (없으면 기본 퀴즈로 시작) |

### 스키마
<!-- ✏️ 본인 구현과 키 이름이 다르면 맞게 수정! (예: hint, history 등 보너스 필드) -->
```json
{
    "quizzes": [
        {
            "question": "Python의 창시자는?",
            "choices": ["Guido", "Linus", "Bjarne", "James"],
            "answer": 1,
            "hint": "네덜란드 출신 개발자입니다."
        }
    ],
    "best_score": 80,
    "history": [
        {"date": "2025-01-10 14:30", "solved": 5, "score": 80}
    ]
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `quizzes` | list | 퀴즈 객체 목록 |
| `quizzes[].question` | str | 문제 내용 |
| `quizzes[].choices` | list | 선택지 4개 |
| `quizzes[].answer` | int | 정답 번호 (1~4) |
| `quizzes[].hint` | str | 힌트 (보너스) <!-- ✏️ 미구현 시 삭제 --> |
| `best_score` | int | 최고 점수 |
| `history` | list | 게임 기록 (보너스) <!-- ✏️ 미구현 시 삭제 --> |

## 8. 코드 구조 (클래스 설계)

### `Quiz` — 개별 퀴즈를 표현
<!-- ✏️ 실제 메서드 이름에 맞게 수정 -->
| 구분 | 이름 | 역할 |
|------|------|------|
| 속성 | `question` | 문제 내용 |
| 속성 | `choices` | 선택지 4개 리스트 |
| 속성 | `answer` | 정답 번호 (1~4) |
| 메서드 | `display()` | 문제와 선택지 출력 |
| 메서드 | `check(user_answer)` | 정답 여부 반환 (True/False) |
| 메서드 | `to_dict()` | JSON 저장용 dict 변환 |

### `QuizGame` — 게임 전체를 관리
| 구분 | 이름 | 역할 |
|------|------|------|
| 속성 | `quizzes` | Quiz 객체 목록 |
| 속성 | `best_score` | 최고 점수 |
| 메서드 | `run()` | 메인 루프 실행 (메뉴 → 기능 분기) |
| 메서드 | `show_menu()` | 메뉴 출력 |
| 메서드 | `play_quiz()` | 퀴즈 출제·채점·결과 표시 |
| 메서드 | `add_quiz()` | 새 퀴즈 입력받아 등록 |
| 메서드 | `show_list()` | 퀴즈 목록 출력 |
| 메서드 | `show_score()` | 최고 점수 확인 |
| 메서드 | `save_state()` | state.json에 저장 |
| 메서드 | `load_state()` | state.json에서 불러오기 (없음/손상 처리 포함) |

<!-- ✏️ 실제 메서드 이름과 다르면 수정, 추가 메서드가 있으면 행 추가 -->

### 클래스 관계
```
main.py
  └── QuizGame (게임 관리자)
        ├── Quiz 객체 여러 개를 quizzes 리스트로 보유
        └── state.json 저장/불러오기 담당
```

> 💡 설계 의도: **Quiz는 "퀴즈 1개"만 알고, QuizGame은 "게임 진행"만 안다.**
> 역할을 분리하면 코드를 수정할 때 어디를 고쳐야 할지 명확해집니다.

## 9. Git 워크플로우

### 커밋 컨벤션
| 태그 | 의미 | 예시 |
|------|------|------|
| `Feat` | 기능 추가 | Feat: 퀴즈 출제 기능 구현 |
| `Fix` | 버그 수정 | Fix: 점수 계산 오류 수정 |
| `Docs` | 문서 작성 | Docs: README 실행 방법 추가 |
| `Refactor` | 구조 개선 | Refactor: QuizGame 책임 분리 |

### 브랜치 전략
<!-- ✏️ 실제 사용한 브랜치명으로 수정 -->

## 11. 배운 점 & 어려웠던 점

<!-- ✏️ 이 섹션이 발표에서 가장 중요! 각 항목 2~3문장씩 솔직하게 작성 -->

### 배운 점
- **클래스 분리의 이유**: 예시) 처음엔 함수만으로 짰는데, Quiz와 QuizGame으로 나누니 "퀴즈 데이터"와 "게임 흐름"이 분리되어 수정이 쉬워졌다.
- **데이터 영속성**: 예시) 변수는 프로그램이 끝나면 사라진다는 걸 체감했고, JSON 저장으로 해결하는 과정에서 파일 입출력을 이해했다.
- **Git 브랜치**: 예시) main을 건드리지 않고 새 기능을 실험할 수 있다는 게 브랜치의 핵심임을 알았다.

### 어려웠던 점 & 해결
- 예시) `state.json`이 손상된 경우 프로그램이 죽는 문제 → `try/except json.JSONDecodeError`로 잡아서 기본 데이터로 복구하도록 해결.
